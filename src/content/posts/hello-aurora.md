## 为什么又做了一个博客

大概每隔两年，我都会重新折腾一次博客。换过 WordPress，用过 Hexo，也在各种笔记应用里安家，最后总是觉得哪里不对：要么太重，要么不属于自己。

这次想清楚了，我要的其实很简单：

- **内容归我所有**：文章就是仓库里一个个 `.md` 文件，`git clone` 一下就能全部带走。
- **没有运行时依赖**：不需要数据库，不需要服务器，不需要每月续费。
- **写作体验要舒服**：打开后台就能写，写完点一下发布，剩下的交给机器。
- **界面要好看**：这一点没有商量余地。

于是有了 Aurora。它是用 Vue 3 + Vite 构建的纯静态博客，所有文章在**构建时**被扫描、解析、渲染成页面，部署到 GitHub Pages 后就是一堆静态文件。

> 内容即文件，发布即提交。这句话基本概括了整个站的设计哲学。

## 它长什么样

前台是一个带极光背景的单页应用：亮暗双主题、玻璃拟态卡片、滚动揭示动画、粒子连线、目录联动、代码高亮与一键复制。后台则是一个完整的写作台，可以在线编辑 Markdown、实时预览、管理草稿，并通过 GitHub API 直接把文章提交回仓库。

```ts
// 新增一篇文章，只需要放一个文件
const files = import.meta.glob('../content/posts/*.md', {
  query: '?raw',
  import: 'default',
  eager: true,
})
```

没有内容接口，没有 CMS 表结构。`src/content/posts/` 目录里多一个文件，站点就多一篇文章。

## 写作到上线的四步

| 步骤 | 发生什么 | 用时 |
| --- | --- | --- |
| 写作 | 后台编辑器写 Markdown，保存在浏览器草稿 | 随你 |
| 发布 | 通过 GitHub Contents API 提交 `.md` 文件 | 1 秒 |
| 构建 | GitHub Actions 触发 `npm run build` | 约 40 秒 |
| 上线 | 产物发布到 GitHub Pages | 自动 |

这套流程最让我满意的地方是：**任何环节都不需要我登录服务器**。哪怕换一台电脑，只要能打开浏览器，就能写一篇新文章并让它上线。

## 关于评论

评论用的是 [Twikoo](https://twikoo.js.org/)，一个轻量的无服务器评论系统。它不追踪用户、不需要注册账号，数据存在你自己的云函数数据库里。本站只是加载一段脚本，填入 `envId` 就能工作——如果还没配置，文章底部会显示一份引导，而不是一片刺眼的空白。

## 最后

这个站不会追热点，也不会有阅读量焦虑。它只是安静地亮着，记录一些技术、一些设计、一些不那么重要但舍不得忘掉的日常。

如果你恰好路过，希望这里的某一行字对你有点用。✦
