## 设计系统不必很大

提到设计系统，容易联想到几百个组件和厚厚的规范文档。但个人项目真正需要的，往往只是把**六类基础决策**固定下来，之后所有页面都引用同一套变量。

## 六件事

1. **颜色**：背景、表面、边框、主文字、次文字、弱化文字、强调色、语义色（成功/警告/危险）。
2. **字体**：无衬线主字体栈 + 等宽代码字体栈，中文优先使用系统字体，避免加载缓慢的 Web Font。
3. **圆角**：三档就够——小 12px、中 18px、大 26px，胶囊用 999px。
4. **阴影**：小、中、大三档，暗色主题整体加深而不是简单反转。
5. **间距**：以 4px 为基数，常用的 8 / 12 / 16 / 24 / 32 组合。
6. **动效**：一条主缓动曲线 + 一组时长档位 + 统一的入场方式。

```css
:root {
  --radius-sm: 12px;
  --radius: 18px;
  --radius-lg: 26px;
  --shadow: 0 12px 36px rgba(31, 41, 85, .09);
  --ease: cubic-bezier(.22, 1, .36, 1);
}
```

## 语义命名，而不是视觉命名

把变量叫 `--surface` 而不是 `--white-card`，主题切换时才不会变成灾难。同理，`--text-soft` 比 `--gray-600` 更能表达用途。

组件里只写语义：

```css
.card {
  background: var(--surface);
  border: 1px solid var(--border);
  color: var(--text);
}
```

这样加暗色主题，只需要覆盖十几个变量。

## 组件的三个状态

每个可交互组件至少要考虑：默认、hover、disabled。再加一个 focus-visible，键盘用户才不会被忽略。

```css
.btn:focus-visible {
  outline: 2px solid var(--accent);
  outline-offset: 3px;
}
```

动效上，hover 用 250–350ms 的位移与阴影，点击用 `scale(.98)` 给一个轻微的回弹感。

## 玻璃拟态的使用边界

`backdrop-filter: blur()` 很好看，但代价不小：多个大面积模糊层会明显增加 GPU 负担，移动端尤其明显。我的做法是：

- 只在导航栏、卡片等**少量**元素上使用；
- 始终配一个不透明的回退背景色；
- 粒子、大面积光晕用静态渐变 + 缓慢位移动画，而不是实时模糊。

## 检查清单

发布前快速过一遍：

- [ ] 亮暗主题下文字对比度是否都够
- [ ] 所有交互元素是否有 hover / focus / disabled
- [ ] 窄屏（375px）下是否有横向溢出
- [ ] `prefers-reduced-motion` 是否生效
- [ ] 代码块、表格、长链接是否可横向滚动

> 一致性带来的可信度，远比一个惊艳但孤立的页面更高。

规范不需要完美，能被坚持执行才有用。
